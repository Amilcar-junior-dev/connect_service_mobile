# 3. Especificação Detalhada de Testes TDD: Onboarding Wizard

## 🧪 Estratégia de Mocks & Isolamento

Para garantir testes unitários 100% determinísticos, rápidos e sem efeitos colaterais:
- **`companyService.createCompany`**: Mockado com `jest.fn()` para retornar respostas controladas (sucesso ou rejeição).
- **`expo-router`**: Mockado com `jest.fn()` para validar chamadas a `router.replace('/(private)/(tabs)/home')`.
- **`global.fetch` (ViaCEP)**: Mockado para simular o payload de resposta JSON da API de CEP.
- **`useOnboardingStore` (MMKV)**: Reseta o estado local via `resetOnboarding()` no `beforeEach` de cada teste.

---

## 📋 Especificação dos Cenários de Teste (`useOnboardingViewModel.test.ts`)

### `[TDD-01]` Inicialização do Wizard no Passo 1
- **Objetivo:** Verificar se o hook é inicializado na primeira etapa com valores limpos.
- **Dado (Given):** A store resetada no estado inicial.
- **Quando (When):** O hook `useOnboardingViewModel` é montado via `await renderHook(...)`.
- **Então (Then):**
  - `result.current.currentStep` deve ser exatamente `1`.
  - `result.current.companyName` e `result.current.slug` devem ser strings vazias (`''`).

---

### `[TDD-02]` Geração Automática de Slug Amigável
- **Objetivo:** Garantir a remoção de acentos e caracteres especiais ao formatar o slug.
- **Dado (Given):** O hook montado no Passo 1.
- **Quando (When):** A função `setCompanyName('Barbearia do Silva & Cia!')` é chamada.
- **Então (Then):**
  - `result.current.companyName` reflete `'Barbearia do Silva & Cia!'`.
  - `result.current.slug` deve ser formatado automaticamente para `'barbearia-do-silva-cia'`.
  - A função auxiliar `generateSlug('Estética & Salão Épico')` deve retornar `'estetica-salao-epico'`.

---

### `[TDD-03]` Validação de Tamanho Mínimo do Nome da Empresa
- **Objetivo:** Impedir o avanço com nomes de empresa muito curtos.
- **Dado (Given):** O usuário digita o nome `'Ab'` (2 caracteres).
- **Quando (When):** A função `handleStep1Next()` é executada.
- **Então (Then):**
  - A função retorna `false`.
  - `result.current.currentStep` permanece no Passo `1`.
  - `Alert.alert` é disparado com mensagem de atenção.

---

### `[TDD-04]` Validação Obrigatória do Passo 2 (Segmento & Porte)
- **Objetivo:** Bloquear a transição para o Passo 3 se os campos do Passo 2 estiverem incompletos.
- **Dado (Given):** O usuário avançou com sucesso do Passo 1 para o Passo 2.
- **Quando (When):** `handleStep2Next()` é chamado sem ter selecionado `segment` ou `teamSize`.
- **Então (Then):**
  - A função retorna `false`.
  - `result.current.currentStep` permanece no Passo `2`.
  - `Alert.alert` solicita a seleção do segmento.

---

### `[TDD-05]` Autocompletar de CEP via API do ViaCEP
- **Objetivo:** Testar a integração remota com a API de CEP.
- **Dado (Given):** O mock de `global.fetch` configurado para retornar `{ logradouro: 'Rua das Flores', localidade: 'São Paulo', uf: 'SP' }`.
- **Quando (When):** A função `setZipCode('01001-000')` é executada com 8 dígitos válidos.
- **Então (Then):**
  - `result.current.address` é atualizado para `'Rua das Flores'`.
  - `result.current.city` é atualizado para `'São Paulo'`.
  - `result.current.state` é atualizado para `'SP'`.

---

### `[TDD-06] & [TDD-07]` Submissão com Sucesso ao Supabase e Redirecionamento
- **Objetivo:** Testar a persistência online e troca de tela.
- **Dado (Given):** `companyService.createCompany` resolvido com sucesso `{ id: 'company-123' }`.
- **Quando (When):** O usuário completa os 3 passos e chama `handleFinishOnboarding()`.
- **Então (Then):**
  - `companyService.createCompany` é chamado com o payload completo (nome, slug, segmento, porte, atendimento).
  - `useOnboardingStore.getState().isOnboardingCompleted` passa a ser `true`.
  - `router.replace` é executado direcionando para `'/(private)/(tabs)/home'`.

---

### `[TDD-08]` Resiliência de Armazenamento Local em Erro de Conexão
- **Objetivo:** Testar a retenção de dados MMKV quando o Supabase falha.
- **Dado (Given):** `companyService.createCompany` rejeitado com erro `'Erro de Conexão'`.
- **Quando (When):** `handleFinishOnboarding()` é executado.
- **Então (Then):**
  - `Alert.alert` informa que os dados foram mantidos no celular.
  - `useOnboardingStore.getState().companyName` preserva a string preenchida pelo usuário.
