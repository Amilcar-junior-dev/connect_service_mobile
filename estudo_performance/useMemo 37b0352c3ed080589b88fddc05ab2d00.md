# 🧠 Guia Completo do `useMemo`

O hook `useMemo` serve para otimizar o processamento da CPU e garantir a estabilidade de referências de Objetos e Arrays em React. Este guia detalha seu funcionamento, cenários de uso, contraindicações e resolve as principais dúvidas.

---

## 1. O que é e Como Funciona?

O `useMemo` executa uma função durante a renderização e **guarda o resultado retornado** por ela na memória (cache).

### Diferença Prática: `useCallback` vs. `useMemo`

- **`useCallback`**: Guarda a **definição da função** (a garrafa térmica com o café dentro).
- **`useMemo`**: Guarda o **resultado retornado pela função** (o café já servido na xícara).

```jsx
const func = () => "Resultado";

// Retorna a FUNÇÃO: () => "Resultado"
const cb = useCallback(func, []);

// Retorna o VALOR: "Resultado"
const memo = useMemo(func, []);
```

## 2. O que são Cálculos "Caros" vs. "Baratos"?

No ambiente mobile, os processadores são mais limitados. Por isso, a definição de custo é baseada no tempo de execução na *JS Thread*:

### 💸 Cálculos Baratos (Não usar `useMemo`)

Operações executadas em frações de microssegundos. O custo do `useMemo` é maior que a própria conta.

- **Exemplos**:
    - Contas matemáticas simples (ex: `a + b`, `x * y`).
    - Formatar strings curtas (ex: ``${user.firstName} ${user.lastName}``).
    - Verificar booleanos simples (`selectedId === item.id`).

### 💰 Cálculos Caros (Usar `useMemo`)

Operações que demoram milissegundos e concorrem com a taxa de atualização da tela (16,6ms para 60 FPS).

- **Exemplos**:
    - Filtrar, ordenar ou mapear arrays médios ou grandes (ex: busca textual em listas a cada caractere digitado).
    - Algoritmos recursivos, buscas em árvores ou grafos.
    - Regex complexos em grandes blocos de texto.
    - *Parsing* de grandes payloads JSON.

> **Regra de Ouro**: Se a operação demora mais de **1 ms** em média (meça com `performance.now()`), considere o `useMemo`. Se demorar mais de **10 ms**, ele é obrigatório.

## 3. O Segundo Uso Vital: Estabilizar Referências

Além de poupar a CPU de cálculos pesados, o `useMemo` serve para manter a mesma referência de memória para **Objetos e Arrays** dinâmicos que são passados como props para filhos com `React.memo`.

```tsx
// ❌ Sem useMemo: O objeto é recriado na memória a cada render, quebrando o React.memo do filho
const customStyle = { color: 'red', margin: 10 };

//  Com useMemo: Referência estável na memória
const customStyle = useMemo(() => ({ color: 'red', margin: 10 }), []);
```

## 4. FAQ: Perguntas e Respostas Fundamentais

### ❓ P: Se o `useMemo` guarda o resultado na memória, por que ele é útil em filtros se o usuário digita letras novas a todo segundo e o valor muda?

**R:** O `useMemo` não congela o resultado para sempre. Ele monitora o seu **Array de Dependências**. Se o texto de busca ou a lista de dados mudarem, ele descarta o cache, roda o filtro novamente e atualiza o cache.

A otimização acontece quando o componente re-renderiza por **qualquer outro motivo** (ex: um temporizador atualizando na tela, mudança de temas ou abertura de modais). Nesses casos, o filtro de dados (operação cara) **não é re-executado**, pois o React reaproveita o resultado que já estava pronto no cache.

## 5. Como testar na prática se o `useMemo` funciona?

### Medição de Tempo com `performance.now()`

Você pode medir o tempo gasto para calcular o valor com e sem o hook:

```tsx
const Parent = ({ itens }) => {
  const [busca, setBusca] = useState('');

  const t0 = performance.now();

  const itensFiltrados = useMemo(() => {
    return itens.filter(i => i.nome.includes(busca));
  }, [itens, busca]);

  const t1 = performance.now();
  console.log(`[useMemo] Tempo de cálculo: ${t1 - t0}ms`);
}
```

- **Primeira renderização (ou quando digita)**: O tempo refletirá o cálculo real (ex: `1.5ms`).
- **Renderizações subsequentes por outros estados**: O tempo cairá para `0.0ms` (instantâneo), provando o uso do cache.
