## `React.memo` (O Guardião do Componente Filho)

<aside>

### **🚀 HIPER RESUMO**

### **1. O que é e o que é Comparação Rasa (Shallow Comparison)?**

- **O que é**: Um HOC (Higher-Order Component) que "envelopa" um componente filho para evitar que ele re-renderize se o pai atualizar, desde que suas *props* não tenham mudado.
- **Comparação Rasa**: É o teste de igualdade padrão que ele faz. Ele compara as props de forma superficial (apenas a primeira camada) usando igualdade estrita (`===`):
    - **Tipos Primitivos** (strings, numbers, booleans): Compara o valor real (`"João" === "João"` → **Igual**).
    - **Tipos de Referência** (objetos, arrays, funções): Compara apenas o endereço de memória (`{} === {}` → **Diferente**). Se a referência mudar (mesmo que o conteúdo interno do objeto seja idêntico), ele re-renderiza.

---

### **2. Quando Usar?**

- Em **componentes filhos puros** (que dão o mesmo resultado visual se receberem as mesmas props).
- Em componentes que estão posicionados abaixo de pais que **re-renderizam com muita frequência** (ex: páginas com temporizadores, formulários ativos, atualizações contínuas de sensores/sockets).

---

### **3. Quando NÃO Usar?**

- Em componentes cujas props **quase sempre mudam** a cada render (você gastará processamento comparando props à toa).
- Em componentes **muito simples e leves** (ex: um botão básico sem lógica). O custo da comparação rasa do `React.memo` pode superar o tempo de renderizar o elemento de novo.
- Em **Páginas/Telas inteiras** (geralmente recebem parâmetros dinâmicos de navegação que mudam de referência a toda hora).

---

### **4. O Combo Necessário (Trabalho em Equipe)**

O `React.memo` **não funciona sozinho** se você passar objetos ou funções. Para que ele funcione da melhor forma, use o combo:

- **`useCallback`**: No componente pai para salvar a referência das funções enviadas nas props.
- **`useMemo`**: No componente pai para salvar a referência de objetos e arrays enviados nas props.
- *Sem eles, o `React.memo` do filho é quebrado no primeiro render do pai.*

---

### **5. Propriedade Opcional (Função de Comparação Customizada)**

Você pode passar uma função de comparação como segundo argumento: `React.memo(Componente, arePropsEqual)`. Serve para ignorar mudanças de referências de objetos ou propriedades irrelevantes.

```
tsx

const ListItem= React.memo(({ title, dynamicStyle})=>{
return<Textstyle={dynamicStyle}>{title}</Text>;
},(prevProps, nextProps)=>{
// Retorne true se as props forem IGUAIS (bloqueia o render)
// Retorne false se forem DIFERENTES (força o render)
return prevProps.title=== nextProps.title;// Ignora se 'dynamicStyle' mudou na memória
});
```

---

### **6. Onde usar com frequência? (Exemplos Simples)**

- Itens individuais de uma lista de rolagem (células de um `FlatList` ou `FlashList`).
- Componentes de Gráficos e Dashboards complexos.
- Tabelas de dados e grades de exibição.
- Componentes de visualização de mídia pesados (players de vídeo, visualizadores de imagem).
- Menus, modais ou sidebars estáticos que ficam sobrepostos a telas dinâmicas.

### O que é e Como funciona?

O `React.memo` é uma função que envolve o seu componente filho. Ele age como um segurança na porta: antes de deixar o componente re-renderizar, ele faz uma **comparação rasa** (*shallow comparison*) das props atuais com as props anteriores.

- Se as props forem **exatamente iguais**, ele bloqueia a renderização e reaproveita o que já estava desenhado na tela.

### Exemplo Prático

- Imagine uma lista de itens:
    
    ```tsx
    import React from 'react';
    import { Text, View, StyleSheet } from 'react-native';
    
    interface ItemProps {
      title: string;
    }
    
    // Usamos React.memo para envolver o componente
    export const ListItem = React.memo(({ title }: ItemProps) => {
      console.log(`Renderizou item: ${title}`); // Se este log rodar sem necessidade, temos um gargalo.
      return (
        <View style={styles.container}>
          <Text>{title}</Text>
        </View>
      );
    });
    
    const styles = StyleSheet.create({
      container: { padding: 10, borderBottomWidth: 1 }
    });
    ```
    

### Onde usar?

- Em itens repetitivos de listas (`FlatList`/`FlashList`).
- Em componentes filhos que estão abaixo de pais que mudam de estado constantemente, mas cujas props do filho não mudam.

### Quando NÃO usar?

- Em componentes extremamente simples (ex: um botão que só renderiza um texto curto estático). O custo computacional que o React gasta comparando as props é maior do que o tempo de renderizar o elemento simples de novo.
- Em componentes cujas props **sempre mudam** a cada renderização (você gastará CPU comparando à toa, pois ele vai re-renderizar de qualquer forma).

## Indo mais a fundo:

### **1. O que é o `React.memo` em detalhes?**

O `React.memo` é um **HOC** (Higher-Order Component). Em termos simples: ele é uma função que recebe um componente React como parâmetro e devolve uma versão "blindada" desse mesmo componente.

### **Como funciona a Comparação Rasa (Shallow Comparison)?**

Por padrão, quando o pai re-renderiza, o React rodará a comparação do `React.memo` propriedade por propriedade do objeto de `props`. Essa comparação usa a regra de igualdade estrita do JavaScript (`Object.is` ou `===`).

Imagine que seu componente recebe as props `{ title: "Item 1", count: 10 }`. Na próxima renderização do pai, o React faz o seguinte teste:

1. `prevProps.title === nextProps.title` -> `"Item 1" === "Item 1"`? **Sim (True)**.
2. `prevProps.count === nextProps.count` -> `10 === 10`? **Sim (True)**.

Como todas as checagens retornaram `true`, o React **aborta** a execução do componente filho e reutiliza o mesmo nó do Virtual DOM que já estava na memória.

### **O Problema com Objetos e Funções (Tipos de Referência)**

Se você passar um objeto nas props: `{ user: { name: "João" } }`. No próximo render do pai:

- `prevProps.user === nextProps.user`?
- Mesmo que o nome continue sendo "João", o objeto `{ name: "João" }` foi recriado na memória em um novo endereço. No JavaScript, dois objetos diferentes nunca são estritamente iguais: `{ name: "João" } !== { name: "João" }`.
- O resultado será **`false`** e o componente vai re-renderizar mesmo com o `React.memo`.

---

### **2. O Superpoder Oculto: A Função Customizada de Comparação**

O `React.memo` aceita um **segundo argumento** opcional, que é uma função de comparação personalizada: `React.memo(Componente, arePropsEqual)`.

Você pode programar essa função para dizer ao React exatamente quando re-renderizar, ignorando certas mudanças de objetos ou funções.

### **Exemplo Prático:**

Imagine que você recebe um objeto de estilo dinâmico que sempre muda de referência na memória, mas você só quer re-renderizar se o `title` mudar:

```
tsx

const ListItem= React.memo(({ title, style})=>{
return(
<Viewstyle={style}>
<Text>{title}</Text>
</View>
);
},(prevProps, nextProps)=>{
// Retorne `true` se as props forem IGUAIS (não re-renderiza)
// Retorne `false` se as props forem DIFERENTES (força a re-renderização)
return prevProps.title=== nextProps.title;
// Ignoramos a mudança de referência do objeto 'style'!
});
```

## Dúvidas:

### **Se um componente não recebe props, o `React.memo` funciona?**

**Sim, funciona perfeitamente!** Na verdade, ele funciona ainda melhor.

### **O que acontece por baixo dos panos:**

Se o seu componente não recebe props, o objeto de props dele é vazio: `{}`. Quando o componente pai re-renderiza, o `React.memo` compara o objeto de props anterior (vazio) com o novo objeto de props (também vazio).

- Como nada mudou (vazio === vazio), a comparação retorna **`true`** (as props são iguais).
- Portanto, o componente filho **nunca re-renderizará devido às ações do pai**. Ele fica "congelado" em cache.

### **⚠️ A única exceção (Quando ele ainda assim re-renderiza):**

O `React.memo` **apenas bloqueia** re-renderizações disparadas pelo **pai**. Se o componente filho que não tem props tiver:

1. **Estado Interno (`useState`)**: Se ele alterar seu próprio estado interno, ele re-renderizará.
2. **Contexto (`useContext`)**: Se ele consumir um Contexto global e os dados desse contexto mudarem, ele re-renderizará.

### **O `React.memo` não funciona em uma "Página" (Tela)? A Página não tem elemento pai?**

No React e React Native, **tudo é uma árvore e tudo tem um elemento pai**.

### **Por que uma Página tem pai?**

Embora você enxergue a "Página" (como a tela de *Home* ou *Perfil*) como o topo do seu arquivo, no aplicativo rodando ela está envolvida por outros componentes invisíveis na árvore:

- O Navigator do **React Navigation** (que gerencia o histórico de telas).
- Providers de tema, de autenticação, de banco de dados (`Realm`, `SQLite`).
- Componentes de `SafeAreaProvider`.

Se o Navigator do React Navigation re-renderizar (por exemplo, porque o usuário abriu uma gaveta de menu ou mudou de aba), **a sua página inteira tentará re-renderizar**. Portanto, colocar `React.memo` na página inteira conceitualmente funciona para protegê-la do Navigator.

### **Mas atenção: Colocar `React.memo` na página inteira geralmente é uma má prática. Por quê?**

As páginas costumam receber propriedades dinâmicas do navegador (como os objetos `navigation` e `route`).

- Esses objetos mudam de referência na memória com muita frequência.
- Isso faz com que a comparação rasa do `React.memo` da página inteira falhe quase 100% das vezes, gastando processamento de comparação à toa.

### **A boa prática de mercado:**

Deixe a sua **Página** sem `React.memo`. Deixe que ela re-renderize, pois ela geralmente é apenas um esqueleto (um contêiner).

Em vez disso, aplique o `React.memo` nos **componentes filhos pesados** dentro dela (como um gráfico complexo, uma lista de produtos, ou um formulário detalhado). Assim, a página re-renderiza em microssegundos (por ser apenas um esqueleto) e os blocos pesados ficam protegidos e estáticos.

3. Marque a caixa: **"Highlight updates when components render"** (Destacar atualizações quando componentes renderizam).
4. No celular/emulador, realize ações que alteram o estado do pai.
    - **Sem React.memo**: Você verá uma borda colorida (verde/amarela) piscar ao redor do componente filho toda vez que clicar no botão do pai.
    - **Com React.memo**: A borda ao redor do filho **não pisca**, provando visualmente que ele foi poupado do ciclo de renderização.

### **Método C: O Gráfico do Flamegraph (React Profiler)**

Para obter dados científicos sobre a economia de performance:

1. No React Native DevTools, vá na aba **Profiler** e clique em **Record** (Círculo azul de gravação).
2. Interaja com o app executando cliques que re-renderizam o pai.
3. Pare a gravação.
4. No gráfico de commits gerado:
    - **Sem React.memo**: O componente filho aparecerá colorido (verde ou amarelo), indicando que ele consumiu milissegundos para renderizar naquele commit.
    - **Com React.memo**: O componente filho aparecerá na cor **cinza** e, ao passar o mouse por cima, a mensagem exibida será: **"Did not render"** (Não renderizou).

## Dúvidas:

### **Se um componente não recebe props, o `React.memo` funciona?**

**Sim, funciona perfeitamente!** Na verdade, ele funciona ainda melhor.

### **O que acontece por baixo dos panos:**

Se o seu componente não recebe props, o objeto de props dele é vazio: `{}`. Quando o componente pai re-renderiza, o `React.memo` compara o objeto de props anterior (vazio) com o novo objeto de props (também vazio).

- Como nada mudou (vazio === vazio), a comparação retorna **`true`** (as props são iguais).
- Portanto, o componente filho **nunca re-renderizará devido às ações do pai**. Ele fica "congelado" em cache.

### **⚠️ A única exceção (Quando ele ainda assim re-renderiza):**

O `React.memo` **apenas bloqueia** re-renderizações disparadas pelo **pai**. Se o componente filho que não tem props tiver:

1. **Estado Interno (`useState`)**: Se ele alterar seu próprio estado interno, ele re-renderizará.
2. **Contexto (`useContext`)**: Se ele consumir um Contexto global e os dados desse contexto mudarem, ele re-renderizará.

### **O `React.memo` não funciona em uma "Página" (Tela)? A Página não tem elemento pai?**

No React e React Native, **tudo é uma árvore e tudo tem um elemento pai**.

### **Por que uma Página tem pai?**

Embora você enxergue a "Página" (como a tela de *Home* ou *Perfil*) como o topo do seu arquivo, no aplicativo rodando ela está envolvida por outros componentes invisíveis na árvore:

- O Navigator do **React Navigation** (que gerencia o histórico de telas).
- Providers de tema, de autenticação, de banco de dados (`Realm`, `SQLite`).
- Componentes de `SafeAreaProvider`.

Se o Navigator do React Navigation re-renderizar (por exemplo, porque o usuário abriu uma gaveta de menu ou mudou de aba), **a sua página inteira tentará re-renderizar**. Portanto, colocar `React.memo` na página inteira conceitualmente funciona para protegê-la do Navigator.

### **Mas atenção: Colocar `React.memo` na página inteira geralmente é uma má prática. Por quê?**

As páginas costumam receber propriedades dinâmicas do navegador (como os objetos `navigation` e `route`).

- Esses objetos mudam de referência na memória com muita frequência.
- Isso faz com que a comparação rasa do `React.memo` da página inteira falhe quase 100% das vezes, gastando processamento de comparação à toa.

### **A boa prática de mercado:**

Deixe a sua **Página** sem `React.memo`. Deixe que ela re-renderize, pois ela geralmente é apenas um esqueleto (um contêiner).

Em vez disso, aplique o `React.memo` nos **componentes filhos pesados** dentro dela (como um gráfico complexo, uma lista de produtos, ou um formulário detalhado). Assim, a página re-renderiza em microssegundos (por ser apenas um esqueleto) e os blocos pesados ficam protegidos e estáticos.
